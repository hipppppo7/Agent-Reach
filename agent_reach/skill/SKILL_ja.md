# Agent Reach

1つのコマンドですべてのプラットフォームを読む：`agent-reach`。読み取り専用で、デフォルトでは1行の JSON を出力する。

作業を始める前に「agent-reach skill を使う（X チャネル）」と一言伝える。この skill は呼び出された後、セッションの最後まで有効で、以下のルールは常に適用される。

## ルートの選び方

- 公開コンテンツは、まず自分の組み込み検索・読み取りツールを使う（`site:ドメイン` を付けてもよい）。本文、コメント、字幕のそれぞれについて取得できたかを個別に確認する。足りていればそのまま回答し、チャネルの追加もログインもしない。
- 組み込みツールが使えない、結果にユーザーが求める部分が欠けている、またはユーザーが求めているのがチャネルの宣言しているサイト内動作である、のいずれかのときに Reach を使う。どんな動作と引数があるか不明なら、まず `agent-reach channels` を実行する。
- チャネルが追加済み（デフォルトチャネル、または `add` 済み）のときは、検索・閲覧はそのサイト用のツールを直接使う。まだ追加していないチャネルでは、検索・閲覧はまずログイン不要の公開 Web ページを試し、結果の `backend: public-web` が取得元を示す。`--backend public-web` は公開 Web ページのみを照会し、`--backend <backend>` はサイト内ツールを指定する。
- プラットフォーム名やリンクは取得元を識別するためだけに使い、それだけでインストールやログインを自動的に始めない。
- 要約（スニペット）、ページの外枠（シェル）、コメント数、字幕トラックの一覧は、本文・コメント・字幕そのものではない。それぞれ区別して伝える。ユーザーがログインをスキップした場合も、取得済みの公開結果はそのまま渡す。

```bash
agent-reach channels                      # 各チャネルの動作と引数
agent-reach <channel> <action> [args]     # 例：agent-reach xiaohongshu search "咖啡" --limit 5
agent-reach read <url>                    # リンクから自動でチャネルを選ぶ
```

## 結果とエラー

- `ok: true` → 内容は `items` にあり、各項目に `title / url / author / published_at / text` がある。元データは `raw` にある。
- `ok: false` → `error.code` を見て、`error.hint` に従う：

| error.code | 対処 |
|---|---|
| `NEED_SETUP` | 依存関係またはキーが不足している。ヒントに従い `agent-reach add <channel>`。キーが必要なときはユーザー本人に提供してもらい、その後 `agent-reach configure <key>` |
| `NEED_LOGIN` | 取得済みの結果は保持し、ログインが必要だとユーザーに伝える。`agent-reach login <channel>` でブラウザが開き、ユーザー本人がログインする。あなたは決して代わりにログインせず、パスワードも求めない |
| `UPSTREAM_BROKEN` | このプラットフォームに一時的な問題がある。`message` はエラー発生時の原文。どのプラットフォームが一時的に使えないか、おおよその原因を、プラットフォーム名で伝える（ツール名は言わない）。原文がツールの古さを示している場合に限り、ユーザーの同意を得てから `agent-reach update` を1回だけ実行する。リトライを繰り返さない |
| `TIMEOUT` | 失敗した段階とチャネルの状態を確認する（`agent-reach doctor --text`）。リトライを繰り返さず、ウィンドウも繰り返し開かない |
| `RATE_LIMITED` | プラットフォームのレート制限。Reach はそのチャネルを一時停止済み。`retry_after_seconds` だけ待つ。バックエンドを切り替えない |
| `PLATFORM_BLOCKED` | プラットフォームが確認（CAPTCHA／不正検知）を求めている。中止し、ユーザーに公式ページで対応してもらう。アカウントもバックエンドも切り替えない |
| `BUSY` | キューで2分間待ってもブラウザが埋まったままだった、またはユーザーがログインウィンドウを開いている。しばらく待つか、ユーザーがログイン完了を伝えてから再試行する。ウィンドウを閉じない、プロファイル（設定）を切り替えない |
| `NOT_FOUND` | コンテンツが存在しない。リンクや ID を確認する |
| `BAD_INPUT` | 引数が正しくない。`agent-reach channels` で使い方を確認する |

`PLATFORM_BLOCKED`、`RATE_LIMITED`、`NEED_LOGIN`、`BUSY` が出たら今回の試行をやめ、アカウント・バックエンド・ブラウザを替えて繰り返しリクエストしない。ネットワーク障害や特定のマシンでの失敗を「プラットフォームはログイン必須」と言わない。

## ログインと専用ブラウザ

ブラウザを使うチャネルはすべて1つの専用ブラウザを共有する（CloakBrowser を優先し、インストールできないときはローカルの Chrome を使う）。デフォルトはヘッドレスでウィンドウを表示せず、10分間アイドルが続くと自動で閉じ、次の呼び出しで自動的に再起動する。並列呼び出しは可能（サブエージェントからの同時照会を含む）：同一プラットフォームは同時に最大2件、全プラットフォーム合計で最大4件まで、超過分は自動でキューに入る。同一プラットフォームでの2回の検索の間は最低10秒空ける。

あるサイトを初めて使うとき、ユーザーの Chrome が OpenCLI 拡張機能に接続済みであれば、プログラムがそのサイトのログインを専用ブラウザへ1回だけ自動コピーし、以後はそれを使い回す。コピーするのはそのサイトだけで、元のブラウザには手を付けない。ログインが失効した場合、またはコピー元がない場合に限り、ユーザー本人に `agent-reach login <channel>` を実行してもらう。更新、コピー元の選択、ログアウトなどの詳細は [セッションと専用ブラウザ](references/sessions.md) を参照：ユーザーがログイン・ログアウト・アカウント切り替えを求めたとき、または `NEED_LOGIN` が出たときに読む。

## プラットフォームごとの注意

- 小红书（Xiaohongshu）の read は文字による説明しか返さない。画像や動画の内容を理解したと主張しない。
- Boss直聘（Boss Zhipin）の検索結果で `salary_encoded=true` のときは、給与の数字を決して推測しない。求人リンクを read して、詳細にある読める形の給与を取得する。
- 各プラットフォームで公開状態のまま何ができ、Reach が何を補うかは [能力の範囲](references/capabilities.md) を参照：ユーザーが「何が取れるか／漏れなく取れるか」を尋ねたとき、または結果の網羅性を判断する必要があるときに読む。

## インストール完了時

`agent-reach setup` の後、`result.installation_report.markdown` をそのままユーザーに表示する。追加・削除・並べ替えをせず、挨拶や表を自分で付け足さない。レポートはプログラムが生成している。

## ユーザーが Agent Reach を管理したいとき

| ユーザーの依頼 | 実行するもの |
|---|---|
| プラットフォームを追加 | `agent-reach add <channel>`。依存関係は自動でインストールされる。ユーザーに伝えるのは、ユーザー自身がやる必要のあること（ログインまたはキーの提供）だけ |
| プラットフォームを削除 | `agent-reach remove <channel>` |
| ログイン／ログイン期限切れ | `agent-reach login <channel>`。開いたウィンドウでユーザー本人がログインする |
| ログアウト | `agent-reach logout <channel>` |
| 状態を見たい／何が使えるか | `agent-reach doctor --text`。実際に試すなら `agent-reach check <channel> --text` |
| アップグレード／更新 | `agent-reach update` |
| アンインストール | まず `agent-reach uninstall --dry-run` の結果をユーザーに見せ、確認を得てから `agent-reach uninstall` |
| 別の AI にも使わせたい | `agent-reach skill link <その AI の skill ディレクトリ>`。現在どこに置かれているかは `agent-reach skill` で確認する |

トラブルシューティング、ブラウザのメンテナンス、アンインストールの詳細は [メンテナンス](references/maintenance.md) を参照：更新が失敗したとき、ブラウザが起動しないとき、またはアンインストールするときに読む。

## 新しいバージョンがあるとき

結果に `meta.update` が含まれていれば、新しいバージョンがある。1回の会話につき1回だけ、ユーザーの言語で、平易な言葉で伝える：

1. 新しいバージョン（`meta.update.latest`）があることを伝える。
2. `meta.update.notes` から1〜3個の要点を選び、何が変わったかをはっきり説明する。
3. 更新するかを尋ねる。ユーザーが同意してから `agent-reach update` を実行する。

## 禁止事項

- 読み取り専用。投稿、コメント、いいね、DM は一切しない。
- ユーザーの代わりにログインしない。パスワード、Cookie などの認証情報を求めない、出力しない。
- 通常の照会では依存関係を変更せず、自動更新もしない。
