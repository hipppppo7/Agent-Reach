# セッションと専用ブラウザ

ユーザーがログイン、ログアウト、アカウント切り替えを求めたとき、または結果が `NEED_LOGIN` を返したときに読む。

## 専用ブラウザ

- ブラウザを使うチャネルはすべて1つの専用ブラウザプロファイルを共有し、ユーザーが普段使う Chrome とは分かれている。プログラムはユーザーの普段のブラウザを閉じたり変更したりしない。
- エンジンは CloakBrowser を優先する。ダウンロードまたはインストールに失敗したときはローカルにインストール済みの Chrome を使い、このフォールバックを記憶して毎回ダウンロードし直さない。ネットワークを直した後は `agent-reach browser setup --retry-cloak` で再試行できる。
- `agent-reach add <channel>` は Node、OpenCLI、エンジン、拡張機能を自動で準備する。ツールはこのリリースでテスト済みのバージョンでインストールされる。Windows で Chrome にフォールバックしている場合、ユーザーが「Chrome に追加」を1回クリックする必要があることがある。
- デフォルトはヘッドレスでウィンドウを表示しない。ウィンドウを表示するのは `agent-reach login <channel>` だけ。そのウィンドウが開いている間、照会はそのウィンドウをそのまま使い、閉じない。ユーザーがログインしている間は、ユーザーがログイン完了を伝えるまで待ってから照会する。ウィンドウが閉じられた後の照会はヘッドレスに戻る。
- 10分間アイドルが続くと自動で閉じ、次の呼び出しで自動的に再起動する。実際のページ操作と Reach の呼び出しでタイマーはリセットされる。ログイン中は定期的に保存されるので、ユーザーがウィンドウを閉じる必要はない。
- 並列実行は可能：同一プラットフォームは同時に最大2件、全プラットフォーム合計で最大4件。超過分はキューに入って最大2分待ち、それでも実行できなければ `BUSY` を返す。同一プラットフォームでの2回の検索の間は最低10秒空ける。ログインウィンドウを開く、ログアウトする、ブラウザを再インストールする操作は、実行中の照会が終わるのを待ってから行われる。
- `agent-reach browser status` で状態を確認、`browser setup` でエンジンと拡張機能を準備、`browser stop` でプログラムが管理するブラウザを閉じる。

## 既存のログインの自動再利用

1. あるサイトを初めて使うとき、ユーザーの Chrome が OpenCLI 拡張機能に接続済みであれば、プログラムはそのサイトのログイン（そのサイトの Cookie のみ）を専用ブラウザへ1回コピーする。ブラウザのディレクトリ全体、他のサイト、パスワードストアはコピーせず、コピー元のブラウザも変更しない。
2. コピーに成功した後は保存したセッションを使い続け、時間経過で再コピーはしない。Cookie があってもログインが有効とは限らない。実際の動作の結果で判断する。
3. ユーザーの Chrome が拡張機能に接続していないときは、自動再利用を約束してはいけないし、それを根拠にユーザーが未ログインだと判断してもいけない。この場合は Reach が保存済みのセッションを使う。
4. このマシンの複数のブラウザがそのサイトにログインしている場合：`agent-reach browser profiles` でコピー元を一覧し、`agent-reach browser use <ID>` で1つを選ぶ。ランダムに切り替えない。
5. `agent-reach login <channel> --import-existing` は、そのサイトのログインを能動的にもう1回コピーする。ウィンドウは開かない。
6. ユーザー本人が専用ウィンドウでログインしたことがある場合、または `logout` / `remove` を実行した場合は、以後自動コピーしない。ログアウトしたはずのログインが復活するのを防ぐため。

## 本人のログインが必要なとき

- 実際に `NEED_LOGIN` が返り、かつ残りのタスクに本当にその経路が必要な場合に限り、ユーザーにログインを頼む。本文の横にログインボタンがあるだけではログインを求められたことにならない。
- `agent-reach login <channel>` は専用ブラウザでそのサイトのログインページを開き、ユーザー本人がログインを完了する。あなたは代わりにログインせず、パスワードを求めず、Cookie を出力しない。
- 返ってきた結果の `next` に後続の手順が書いてあれば、それに従う。一部のネイティブツールのチャネル（雪球（Xueqiu）など）は、ログイン後にさらに `agent-reach login <channel> --sync` を実行する必要がある。
- ユーザーが完了したら、元の動作をもう一度実行して確認する。

## プラットフォームごとの違い

- Boss直聘（Boss Zhipin）のサイト内検索は OpenCLI を通り、専用ブラウザを共有する。求人の詳細が上流の誤判定でログインを要求してきても、ユーザーに何度もログインさせない。
- Bilibili（B站）は字幕を読むときだけ、既存のログインを Bilibili 公式のコマンドラインツールに渡す。通常の検索ではブラウザを準備しない。
- 雪球（Xueqiu）のコミュニティ系の動作にはログインが必要。セッションは数時間以内に期限切れになり、期限切れ後はログイン手順を繰り返す。

## ログアウトと削除

- `agent-reach logout <channel>`：専用ブラウザ内のそのサイトのログインと、チャネル自身の状態を消去する。他のサイトは残す。
- `agent-reach remove <channel>`：チャネルを削除し、同時にそのサイトのログインとストレージを消去する。他のサイトは残す。消去に失敗した場合はチャネルの記録を残してエラーを返すので、ユーザーは再試行できる。
- どちらを実行した後も、そのサイトのログインは自動コピーされなくなる。
